# Image publication activation

With no `ECR_PUBLISHER_ROLE_ARN` repository variable, the main workflow's **Publisher activation** job reports publication pending and requests no AWS credentials. Existing ECR images remain available. Setting `MIDKERNEL_APPROVED_AWS_ACCOUNT_ID` alone does not activate publishing. An absent activation variable remains disabled even if the account configuration is stale or malformed. The separate OIDC claims debug job does not publish images.

1. An authorized infrastructure operator selects the approved AWS account independently of any role ARN or image URI, then follows `midkernel/infra`'s reviewed bootstrap in `docs/operations.md`. Provision and verify `arn:aws:iam::<APPROVED_ACCOUNT_ID>:role/midkernel-github-publish-runner` with exact main-only OIDC trust and the documented repository-scoped ECR permissions. Configure protected apply and private saved-plan storage as required there.
2. After separate operational approval and bootstrap, set the repository's Actions variable **MIDKERNEL_APPROVED_AWS_ACCOUNT_ID** to the approved account's exact 12 ASCII digits, without whitespace. There is no default or inference from another variable. Separately set **ECR_PUBLISHER_ROLE_ARN** to the complete dedicated-role ARN in that same approved account. Any other nonempty role, including a legacy role, another account, a different role path, or partition, fails validation. These placeholders are documentation, not configuration values.
3. Dispatch **CI** from `main`. Confirm tests, image build, and **Push to ECR** all succeed, and record the published commit and digest. Readiness checks repository, branch, event, and the exact configured pair before exposing validated role/account outputs. Credentials use that validated role, and publication checks the ECR login registry against that validated account and the existing region. Readiness success alone does not prove role availability or publication. Complete this public runner release before publishing the private overlay that consumes its base image.
4. After both publisher migrations succeed, remove transitional legacy trust through a reviewed infrastructure change. Do not set app runtime image configuration from this repository.

The operator can unset the activation variable to pause future publication while retaining validation and existing images. This does not roll back images already published. Pull requests never receive AWS publisher credentials. The public Docker build remains credential-free and runs on pull requests and main. Source cleanup itself performs none of the configuration, IAM, dispatch, or release steps above.

## Standalone ECS example

`pipelines/security-review.py` requires the explicit process environment variable `MIDKERNEL_APPROVED_AWS_ACCOUNT_ID` with the same 12 ASCII digit contract before constructing its ECS graph. It has no default account or local-target branch. Review the image and fill the example's network configuration privately before any execution.

`examples/task-definition.json` contains deliberately non-executable `REPLACE_EXECUTION_ROLE_ARN`, `REPLACE_TASK_ROLE_ARN`, and `REPLACE_AGENT_IMAGE` placeholders. The AWS CLI does not interpolate environment variables in JSON. Render and review a private copy before use; do not commit rendered identifiers. No rendering or deployment is part of source cleanup.
